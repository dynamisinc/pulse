# Pulse User Guide

**Applies to:** Pulse as of October 2026.

Pulse simulates the social-media environment that people work in during an emergency-management
exercise. Players see a realistic social network for the exercise. Exercise staff plan, run and
watch it from staff screens.

This guide explains how to use Pulse to plan an exercise, run it, and bring players into it. It is
written for exercise practitioners. You do not need a technical background to follow it.

## Who each guide is for

| Role | What you do in Pulse | Start with |
|---|---|---|
| **Planner / Exercise admin** | Create the exercise. Set its name, schedule, look and markings. Add players and hand out sign-in links, cards and today's word. Archive the exercise afterwards. | [Getting started](getting-started.md), then the [Planner guide](planner-guide.md) |
| **Controller** | Run the exercise on the day. Start and end it, fire injects from the run sheet, post as personas, review AI-drafted posts, pause or freeze the world, and take down posts. Controllers can also manage participants and exercises. | [Getting started](getting-started.md), then the [Controller guide](controller-guide.md) |
| **Evaluator** | Watch the exercise without changing it. Evaluators get a read-only view of the Controller Console and can open the exercise report. *The Evaluator Dashboard is not yet on live data. Evaluator guidance will follow when it is.* | [Getting started](getting-started.md) |
| **Participant (player)** | Use the exercise's social network as you would a real one: read, post, reply, like, repost and pin. | The one-page [Participant guide](participant-guide.md). Print it or email it to players. |

Everyone on the staff side should also keep the [Glossary](glossary.md) and
[Troubleshooting](troubleshooting.md) pages to hand.

## How to read this guide

- **Steps are numbered.** Do them in order. Button and field names appear in **bold**, spelled
  exactly as they are on screen.
- **Screenshots** show what you should see. Your exercise's names, colours and people will differ.
- **"Not yet available"** marks something people often expect that Pulse does not do yet. We say so
  plainly so that you can plan around it.
- **"Rolling out"** marks a feature in the current update that may not be on your server yet. If you
  do not see it, it has not reached your server.
- **Times.** Players only ever see *scenario time*, which is the exercise's own clock. Staff screens
  show scenario time and real time side by side. See [Scenario time](getting-started.md#scenario-time).

### What Pulse does not do yet

So that you can plan around them:

- **Only the social network is available.** The news site, TV, newspaper, wire service, press room
  and weather service in the Pulse design are not available yet.
- **No direct messages.** Players cannot message each other privately yet.
- **No mobile apps.** Players use Pulse in the web browser on their phone, tablet or computer. There
  is nothing to install.
- **The Evaluator Dashboard is not on live data yet.** Evaluators can use the read-only Controller
  Console and the exercise report for now.
- **Emergency alerts.** Pulse has a space for an emergency-alert bar on player screens. Controllers
  cannot publish alerts to it yet.

## Keeping this guide current (for the Pulse team)

The guide only stays useful if it keeps up with the product. This is the practice we intend to
follow:

- **Screenshots are regenerated, not hand-captured.** The images in `img/` come from the capture
  tool in `tools/guide-screenshots`. When a screen changes, re-run the tool rather than replacing
  images by hand. Keep the file names in this guide unchanged so that the links keep working.
- **Every story says whether it changes the guide.** The story template carries a "user-guide impact"
  line. Fill it in with "none", or with the page and section that need updating. The change to the
  guide ships with the story.
- **Use the words on the screen.** Check button and field labels against the running app, not
  against the design documents.
- **Update "Applies to" at the top of this page** whenever a release changes what the guide
  describes. When a "Rolling out" feature reaches every server, remove the marker.
